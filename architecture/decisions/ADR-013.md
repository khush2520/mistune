# ADR 013 · Put the requested outcome first at intake

**Status**

Trial revision after the initial hosted attempts.

## Context

In the first free trials the requirements model asked what `--output -` should do even though the issue specified stdout and preserving a dash file. Other issues received similar redundant questions. One request timed out.

## Decision

Feed the local model the A1 acceptance and validation sections directly, with two contrasting examples: an issue with a measurable outcome and an issue missing the example needed to test it. Distinguish broken current behavior from requested behavior. Keep the structured spec gate and use a smaller JSON grammar for intake.

## Consequences

A stopped run still records unresolved assumptions. The local model reads less material, and the requirements prompt leaves nonessential A1 material to the full skill document. The new trial measures operating behavior with this prompt revision rather than treating the first run as a success.
