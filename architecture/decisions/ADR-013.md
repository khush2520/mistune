# ADR 013 · Put the requested outcome first at intake

**Status**

Trial revision after the initial hosted attempts.

## Context

In the first free trials the requirements model asked what `--output -` should do even though the issue specified stdout and preserving a dash file. Other issues received similar redundant questions. One request timed out.

## Decision

Feed the local model the A1 acceptance and validation sections directly, with two contrasting examples: an issue with a measurable outcome and an issue missing the example needed to test it. Distinguish broken current behavior from requested behavior. Keep the structured spec gate and use a smaller JSON grammar for intake.

## Consequences

A stopped run still records unresolved assumptions. The local model reads less material, and the requirements prompt leaves nonessential A1 material to the full skill document. The new trial measures operating behavior with this prompt revision rather than treating the first run as a success.

A follow-up run cleared requirements for four concrete issues and appropriately stopped the vague issue. The next bottlenecks were a design timeout, unmatched source replacements, and invalid generated tests. The final revision gives the model plain source context, shorter plans, and a runner-owned generated test path.

The restored F1 trial passed design but both implementation answers failed exact-text matching. The implementer now receives numbered lines and returns bounded, non-overlapping replacement ranges. The file allowlist, Python parse check, wheel build, and test gate still apply.

In the first line-range trial the agent moved output handling ahead of rendering. Its generated tests and two baseline tests caught the regression. The design index now shows both declarations and consumers of CLI options, along with their enclosing function names. The design prompt directs the agent to the existing handler for a parsed option.
