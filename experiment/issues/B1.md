# An explicitly empty message should work in the CLI

My script sometimes calls `python -m mistune --message ""` when a template has nothing in it. The command tries to fall back to stdin and eventually exits with an error. Passing an empty string is intentional here. I want the command to succeed and produce the same empty rendered result as an empty Markdown file. That includes creating an empty file when I pass `--output result.html`. If I pass an explicit message along with a file, the message should still win, even when the message is empty.
